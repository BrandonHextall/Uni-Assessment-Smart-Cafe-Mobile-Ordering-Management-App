**Coursework Objective**

Creating a mobile app for a café, supporting customer ordering (and management operations)



Should provide: good UX, secure authentication, use database, order management and other features using appropriate technologies.



Should implement/simulate essential functionality from the other role (admin) to demonstrate a complete workflow. Eg implement an automated order status update to simulate Admin actions.



**2. Functional Requirements**

Customer application must allow users to:

&#x09;Register and log in securely

&#x09;Browse café menu (including drinks, cakes and other available 	products)

&#x09;View product information (including prices, descriptions and 	availability)

&#x09;Search/filter menu items

&#x09;Add products to shopping cart

&#x09;View, update, remove items from shopping cart

&#x09;Place an order and receive conformation

&#x09;View previous order and track current order statuses

&#x09;Submit feedback and product/service ratings

&#x09;Receive notifications when an order status changes



We may simulate order processing using a timer, background processes, or test administration interface. However, the process must demonstrate actual application logic and meaningful data updates.



**3. Advanced Technical Integration**

Must implement at least one meaningful advanced integration:

&#x09;**REST API** - connect to an external service to retrieve or exchange 	useful data

&#x09;**Artificial Intelligence** - provide intelligent product 	recommendations or feedback analysis

&#x09;**Machine Learning** - predict popular products or analyse ordering 	patterns

&#x09;**Data Analytics** - Analyse order history, revenue, or customer 	behaviour

&#x09;**Cloud Services** - implement cloud-based data storage or 	notifications

&#x09;**Other Integration** - propose a suitable external service or 	technology relevant to the project



A basic API or external service integration can meet core requirements if implemented correctly and includes appropriate data/error handling, security considerations and testing.



**4. Software Design, Architecture and Technical Requirements**

**Application must be developed using Android Studio and Kotlin.**



May choose Jetpack Compose or XML for UI. Select and justify appropriate software architecture or design approach.



Implementation must demonstrate:

&#x09;Application must be developed using Android Studio and Kotlin

&#x09;Clear software requirements and appropriate application design

&#x09;Suitable UI/UX

&#x09;Database integration (SQLite, Room, Firebase or other justified 	solution)

&#x09;Secure authentication and role-based access where applicable

&#x09;Data validation, exception handling, and appropriate error messages

&#x09;Effective integration of APIs or external services

&#x09;Appropriate consideration of privacy, security and ethical issues

&#x09;Testing and evaluation of key functionality



**5. Real-World Development: Agile Working and Stakeholder Engagement**

**Coursework intended to simulate real-world software development environment**



**Lab tutor will act as client/stakeholder.**



Expected to develop application incrementally, demonstrate progress during weekly sessions and respond professionally to feedback.



Based on weekly progress, client may request to:

&#x09;Modify an existing feature

&#x09;Add new functionality

&#x09;Improve UI/UX

&#x09;Change database structure or application workflow

&#x09;Fix identified issue

&#x09;Investigate/ integrate an additional technology

These are part of learning experience and reflect changing requirements of real software projects.

**Any changes must be discussed, documented, prioritised, and implemented where appropriate and feasible within project scope.**



Must not make undocumented changes to agreed requirements.



**6. GitHub, Version Control and Change Management**

Must maintain appropriate GitHub repo containing source code and dev documentation:

&#x09;Create repo at beginning of project

&#x09;Commit and push regularly, including meaningful dev activities

&#x09;Maintain a record of changes and new requirements

&#x09;Use clear and descriptive commit messages

&#x09;Keep project backlog updated

&#x09;Record issues, bug fixes and improvements

&#x09;Maintain appropriate project documentation

&#x09;Use branches and pull requests where appropriate

Every significant requirement change/ stakeholder request must be recorded and traceable to the relevant implementation/ GitHub commit.



**7. Testing, Security and Evaluation**

Must demonstrate appropriate testing of application:

&#x09;Core functional requirements

&#x09;Database operations and data consistency

&#x09;Authentication and access control

&#x09;Input validation and error handling

&#x09;UI and navigation

&#x09;API integration and failure scenarios

&#x09;Advanced functionality we implemented.

Include a test plan, test cases, expected results, actual results, and evidence of testing

Must also discuss relevant security and privacy considerations including secure handling user data and credentials.

Evaluation should identify strengths, limitations, challenges and possible future improvements of the applications.



**8. Technical Report and Submission Evidence**

Should prepare a technical report documenting work:

&#x09;**Introduction and Requirements:** problem, objectives, user roles, 	functional and non-functional requirements.

&#x09;**Project Planning:** PRD, backlog, development stages, planning 	decisions.

&#x09;**System Design:** Architecture, UI/UX design, database design, and 	relevant diagrams.

&#x09;**Implementation:** key functionality, technical decisions, API/AI 	integration, implementation challenges.

&#x09;**Testing and Security:** test plan, results, evidence, security 	considerations.

&#x09;**Agile Development and Change Management:** weekly progress, client	meeting records, change requests, and GitHub evidence.

&#x09;**GenAI Usage Declaration:** full disclosure of GenAI, or confirmation 	none was used.

&#x09;**Evaluation and Relection:** achievements, limitations, lessons	learned, future improvements.

&#x09;**References:** appropriate technical and academic references.



Submission must provide access to:

•	The Android Studio project and relevant source code.

•	The GitHub repository and development history.

•	The individual technical report.

•	The product backlog, change log, and client meeting records.

•	Testing evidence.

•	Any additional materials required for the demonstration.

•	Demonstrate database operations and external integrations.

•	Discuss implementation decisions, security, and testing.

•	Explain stakeholder changes and how they were managed.

•	Show relevant GitHub commits and development evidence.

•	Explain any GenAI assistance used.
